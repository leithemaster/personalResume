Site

The problem

A web platform used by internal teams, built to make support requests easier to handle: easier to raise, easier to follow, easier to close.

Plan

The design

As primary UI/UX designer I owned the design process end to end. I started with user flows to settle what each request had to pass through, then wireframes to fix the layout before any visual decision, then high-fidelity mockups.

UX decisions were tested and brought to stakeholders in feedback sessions. The design was iterated across teams and went to build only after stakeholder approval.

Structure

The handoff

I worked through handoff with the developers, covering HTML/CSS layout and the styling of Angular components, so what was built matched what was approved.

Every screen was reviewed against Section 508 guidelines. Accessibility was part of the drawings, not a pass at the end.

Form

The outcome

The design went to build only after stakeholder approval, and the developers had everything they needed to match it: layout, component styling and a Section 508 review of every screen.

Site

The problem

NexGen is an internal web application at USCIS. The work was new features, built across the full stack.

Plan

The design

I was hired to build, and I also contributed to visual and interaction design. I joined design review sessions, kept UX feedback loops running between design and development, and took part in Agile sprint planning.

The aim of that loop was plain: improve the usability and performance of core features.

Structure

The build

Frontend, React. UI components, feature enhancements and hook-based logic.

Backend, Spring. API integration, PostgreSQL queries and business-logic updates.

Form

The outcome

New features shipped across the stack, from React components and hooks down to Spring Boot logic and PostgreSQL queries, with the usability and performance of core features improved along the way.
